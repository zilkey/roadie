Data model, schema, who can see what, user stories, and simple screens for the Ingrid Avison Band app. Firebase (Firestore + Google sign-in), Next on App Hosting, one MCP server for AI. Campaigns are left out for now.

Words

The app speaks plain language. The schema uses precise names. This is the mapping, so the screens and the database never drift apart.

Pitchpitch. One thing we're going after.
Venuevenue. A physical room or stage.
Promoterpromoter. Whoever books: a buyer, a venue group, a nonprofit.
Festival or Concert seriesfestival, with type festival or series. Lists say "Festivals & series".
UMS 2027edition. One dated run of a festival. The app just shows name + year.
Contactscontact. Bookers and buyers. Not musicians.
Artistartist. Ingrid Avison Band. The only one for now.
Full band, Duo…configuration. A way the artist plays, with its usual musicians.
Who's playingpersonnel. The musicians on this show.
Musiciansmusician. Anyone who plays. Subs need no login.
Filesfile. A Google Drive link: chart, demo, recording, receipt.
Moneyledger. Every dollar in or out, never edited.

Ground rules

  • One door for writes. Browsers read Firestore directly. Every write goes through server commands (app, MCP, scripts). Rules deny all client writes.
  • Strict shapes. One Zod schema per collection, shared by app, MCP, import and restore. Unknown fields are rejected. Values are normalized.
  • Roles live in the sign-in token. The server sets a role custom claim (and musicianId) on each Firebase account. Rules check request.auth.token.role without reading any document. The users doc mirrors it for display.
  • Show is one thing. It is stored as shows + showDeals only so members can't read the money. Commands and MCP tools always write both together.
  • No duplicates. Venues, promoters, festivals and contacts carry a matchKey. A create that matches merges instead.
  • Money in cents. Integers only. Ledger entries are never edited or deleted; mistakes get a reversal entry.
  • Soft delete + history. Nothing is hard-deleted. Every change writes a history record with a runId, so a whole AI session can be undone at once.
  • Drive for files. Recordings, charts, receipts and posters live in Google Drive, ideally in the one band folder. The app stores the Drive file ID and link, and checks that every band member can open each file.
  • Nightly backup. A GitHub Action dumps every collection to JSON in a private repo.

Who sees what

User stories

Everyone signs in with Google. An admin adds a person's email first; anyone else is turned away.

Screens

Every screen comes in a phone and a web version. Phone: five tabs along the bottom. Web: the same five down the left. Members see four of them.
